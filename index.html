Tree Balance & Time Complexity Analysis

Analyze why maintaining balanced height O(log n) prevents degradation into O(n) linear linked lists.

Balanced BST

Height: O(log n)

Splits search space in half at every step. Ideal logarithmic search efficiency. 

        (50)
       /    \
     (30)   (70)
    /   \   /   \
  (20) (40)(60) (80)
Search Time: O(log n)
Max Comparisons (N=7): 3 steps

Skewed BST (Worst Case)

Height: O(n)

Occurs when inserting sorted keys (e.g. 10, 20, 30, 40, 50). Degenerates into a Linked List. 

(10)
   \
   (20)
      \
      (30)
         \
         (40)
            \
            (50)
Search Time: O(n)
Max Comparisons (N=5): 5 steps
